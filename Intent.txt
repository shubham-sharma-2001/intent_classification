🧠 CORE REQUIREMENTS

---

1. Tokenizer

- Normalize text (lowercase, remove punctuation)
- Lemmatization
- Output tokens

---

2. RDF GRAPH (Apache Jena Fuseki)

Ontology Design

Define:

- Class: Intent
- Properties:
  - hasKeyword
  - mapsToIntent

Example triples:

:buy rdf:type :Keyword
:buy :mapsToIntent :BUY

:purchase :mapsToIntent :BUY
:sell :mapsToIntent :SELL

---

3. GRAPH QUERY (SPARQL)

- Query Fuseki endpoint
- Input: token
- Output: intent

Example SPARQL:

SELECT ?intent WHERE {
?word :mapsToIntent ?intent .
FILTER(?word = "buy")
}

---

4. GRAPH AUTO-UPDATE (CRITICAL)

After human validation:

Insert new triples into Fuseki

Example:

INSERT DATA {
:enter :mapsToIntent :BUY .
}

---

5. EMBEDDING LAYER

Use:

nomic-ai/nomic-embed-text

Store vectors in:

- FAISS OR Chroma

Intent vectors:

BUY:

- "buy stock"
- "purchase shares"
- "invest in stock"

SELL:

- "sell stock"
- "exit position"
- "close trade"

---

6. EMBEDDING LOGIC

- Convert query → embedding
- Compute cosine similarity
- If similarity > 0.85 → return intent

---

7. LLM FALLBACK

Use:

openai gpt oss 20b

Prompt:

Classify into BUY, SELL, UNKNOWN
Return only one word

---

8. 🚨 HUMAN VALIDATION

If LLM is used:

Ask:

"Detected intent is BUY. Is this correct? (yes/no)"

If YES:

- Accept
- Update RDF graph

If NO:

- Ask correct intent
- Update RDF graph

---

9. RULE VALIDATOR

BUY:

- optional asset

SELL:

- optional asset

UNKNOWN:

- always valid

---

10. CONFIDENCE LOGIC

Priority:

Graph > Embedding > LLM

---

11. CLI INTERFACE

Interactive CLI:

User enters query
System prints:

- intent
- source (graph/embedding/llm)
- confidence
