You are a senior AI architect and Python backend engineer.

Build a production-grade Hybrid Intent Extraction System that mimics human reasoning and extracts ONLY the true actionable intent from noisy natural language.

---

🎯 OBJECTIVE

The system must:

1. Accept any natural language input (messy, long, conversational)
2. Extract ONLY the actionable intent sentence
3. Classify into STRICT intents:
   - BUY
   - SELL
   - UNKNOWN
4. Extract:
   - Asset (Tesla, Apple, etc.)
   - Quantity (10, 100, etc.)
5. Ignore:
   - Confusion ("I think", "maybe")
   - Questions ("should I", "what if")
   - Negation ("don't want", "never")
   - Sarcasm (handled via LLM fallback)
6. Achieve:
   - ~98–99% intent accuracy
   - ~100% safe execution

---

🧠 CORE PRINCIPLE

DO NOT classify entire input.

Instead:

1. Break into clauses
2. Filter noise
3. Detect real action
4. Extract intent

🔥 MODULE IMPLEMENTATION DETAILS

---

[1] Sentence Splitter

Goal:

Split input into meaningful clauses.

Use:

- spaCy OR regex

Logic:

- Split on:
  - ".", ",", "but", "and", "however"

Example:

"I am confused but I want to buy Tesla"

→ ["I am confused", "I want to buy Tesla"]

---

[2] Intent Signal Scorer ⭐

Goal:

Filter actionable sentences

---

Define scores:

buy/sell/purchase → 1.0
want to → 0.9
plan to → 0.7
thinking → 0.5
maybe/confused → 0.3

---

Rule:

if score < 0.8:
discard sentence

---

Pseudo-code:

for sentence in sentences:
score = calculate_score(sentence)
if score >= 0.8:
keep

---

---

[3] Negation Handler ⭐

Goal:

Remove sentences where action is negated

---

Detect:

not, never, don’t, avoid, refuse

---

Rule:

if negation exists AND near action verb:
discard sentence

---

Example:

"I don't want to buy Tesla" → REMOVE

---

Advanced:

Use dependency parsing (spaCy) to detect scope

---

---

[4] Entity Extractor ⭐

Goal:

Extract asset and quantity

---

Methods:

- Regex for numbers
- Dictionary for stock names
- spaCy NER (optional)

---

Example:

"buy 10 Tesla shares"

→ asset = TESLA
→ quantity = 10

---

Rule:

if asset AND quantity:
mark sentence HIGH PRIORITY

---

---

[5] Graph Resolver (PRIMARY ENGINE)

Goal:

Resolve synonyms → intent

---

Use:

- Apache Jena Fuseki
- SPARQL queries

---

Example query:

SELECT ?intent WHERE {
?word :mapsToIntent ?intent .
FILTER(?word = "purchase")
}

---

If match found:

return intent, confidence = 1.0

---

---

[6] Embedding Similarity

Goal:

Semantic fallback

---

Use:

- nomic-ai/nomic-embed-text
- FAISS / Chroma

---

Process:

- Convert query → vector
- Compare with stored intent phrases

---

Threshold:

if similarity > 0.85:
return intent

---

---

[7] LLM Reasoner (LAST FALLBACK)

Goal:

Handle sarcasm, indirect intent

---

Prompt:

"Classify intent into BUY, SELL, UNKNOWN. Return only one word."

---

Use ONLY if:

- graph fails
- embedding < threshold

---

---

[8] Aggregation Engine

Goal:

Select best intent from multiple candidates

---

Rules:

- highest confidence
- contains entity
- highest intent score
- latest actionable sentence

---

---

[9] Rule Validator

Rules:

BUY requires asset
SELL requires asset
UNKNOWN always valid

---

---

[10] Confidence Engine

Priority:

Graph > Embedding > LLM

---

Decision:

confidence > 0.9 → accept
else → validate

---

---

[11] Human Validation

Trigger:

if LLM used OR low confidence

---

Flow:

Ask user:
"Detected intent is BUY. Confirm?"

If YES → proceed
If NO → ask correct intent

---

---

[12] Graph Learning Controller

Goal:

Improve system over time

---

Rule:

ONLY learn if:

- human confirmed
- confidence high

---

Add mapping:

"put money" → BUY

---

Prevent:

- duplicate entries
- ambiguous mappings

---
